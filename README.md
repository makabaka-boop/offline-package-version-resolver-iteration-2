# 离线软件包依赖求解器

一个只使用 Python 标准库的命令行/容器求解器。它读取一份离线目录 JSON，输出满足根需求、依赖闭区间约束与已知冲突互斥约束的完整可安装集合；默认情况下若不存在这样的集合，只输出 `UNRESOLVABLE`。显式加上 `--relax-root-requirements` 后，可在原请求无解时撤销最少的整条根需求以生成完整让步方案。

## 目录限制

- 最多 10 个唯一包名；包名必须为非空、可见 ASCII 字符（不含空格）。
- 每个包有 1～4 个正整数版本。
- 每个版本可声明 0 个或多个依赖，依赖要求为闭区间 `[lower, upper]`。
- 根需求也使用闭区间。
- 可选 `conflicts` 声明已知不兼容的精确版本组合：每项为 `[[包名, 版本], [包名, 版本]]`，两个端点必须是目录内**不同**包的**已知**版本；整份列表不得有重复（含逆序重复）。
- 冲突是双向互斥约束：两个端点版本不得同时出现在最终集合中。它不产生依赖，也不会把闭包外的包保留下来。
- 依赖环允许；环上每个被选版本必须被所有入边区间接受。
- 最终集合必须**恰为**根需求沿所选版本依赖可达的闭包：不能缺少被依赖包，也不能保留闭包外的已装包。

## 优化目标（按优先级）

在所有可行解中依次选择：

1. **变更包数最少**：相对 `installed`，新增、删除、改版都算 1 个包。
2. **最终包数最少**。
3. **版本向量字典序最大**：按目录中全部包名排序，未安装位置记作版本 `0`。

例如目录名顺序为 `("a", "b")` 时，只安装 `b=2` 的向量是 `(0, 2)`。

## 根需求放宽模式

默认求解必须逐字满足请求；只有显式传入 `--relax-root-requirements`（简写别名 `--relax-roots`）才启用让步。规则如下：

1. 先求解原请求。原请求有解时，输出与默认模式相同的 JSON 选择。
2. 原请求无解时，只允许暂时撤销**整条根需求**（删除该包的根约束），不得修改依赖、冲突、目录版本或 `installed`。
3. 先选择撤销条数最少的根集合；撤销条数相同时，按撤销包名排序后的列表做字典序裁决。
4. 对保留根需求，继续按“最少变更、最少最终包数、最大版本向量”的原目标求**完整闭包**。
5. 求解器会把每个被撤销需求单独重新加入保留集合并确认仍无解，以保证让步最小且确有必要。
6. 每个候选根集合都在独立的求解状态中搜索；约束传播和回溯分支不会跨集合泄漏。

让步报告为一行 JSON，例如：

```json
{
  "revoked_root_requirements": [
    {"package": "app", "interval": [2, 2]}
  ],
  "installation": {"lib": 2},
  "changes": [
    {"package": "app", "action": "removed", "before": 2, "after": null},
    {"package": "lib", "action": "added", "before": null, "after": 2}
  ]
}
```

`changes` 只列出相对 `installed` 发生变化的包：新增为 `added`，删除为 `removed`，版本改变为 `changed`；未列出的包保持原版本。即使撤销全部根需求，结果也必须是完整的空闭包 `{}`。

`installed` 中允许出现目录里已经不存在的版本号（视为过期安装，升级或删除算一次变更）；但 `installed` 中的包名、根需求包名和依赖包名都必须在目录内，否则按格式错误直接拒绝。根需求为空对象是合法输入，表示目标闭包为空，当前已装包都应删除。

## 输入格式

```json
{
  "packages": {
    "app": {
      "1": {"dependencies": {"lib": [1, 2]}},
      "2": {"dependencies": {}}
    },
    "lib": {
      "1": {"dependencies": {}},
      "2": {"dependencies": {}}
    }
  },
  "root": {
    "app": [1, 2]
  },
  "installed": {
    "app": 1
  },
  "conflicts": [
    [["app", 2], ["lib", 1]]
  ]
}
```

- `packages`、`root`、`installed` 三个顶层字段均为必填，`conflicts` 可省略或为空数组；不允许未知字段。
- `dependencies` 可省略或为空对象。
- 版本键必须是无符号正整数的十进制字符串（如 `"1"`，不接受 `"01"`、`"1.0"`）。
- 区间必须是恰好两个整数组成的数组，且满足 `1 <= lower <= upper`。
- 每个 `conflicts` 端点是 `[包名, 版本]` 二元数组；版本为整数，且必须是该包在目录中的已知版本（与 `installed` 不同，不接受过期版本）。
- 布尔值不会被当作整数接受；JSON 重复对象键会被拒绝。

## 输出与退出码

- 有解：标准输出打印一个 JSON 对象，键按包名字典序排列，如 `{"app": 2, "lib": 2}`；退出码 `0`。
- 无解：标准输出打印一行 `UNRESOLVABLE`；退出码 `0`。不会输出部分计划。根需求与冲突共同导致无解时也只输出该标记。
- `--relax-root-requirements`（或 `--relax-roots`）且原请求无解：输出上述根需求放宽报告；退出码 `0`。原请求有解时仍输出普通选择 JSON。
- JSON/契约格式错误、目录外依赖、未知或同包冲突等非法 `conflicts`：无论是否启用放宽模式，错误信息都写入标准错误；退出码 `2`；标准输出不产生计划，格式错误不会被包装成 `UNRESOLVABLE` 或让步报告。

## 本地运行

```bash
# 从标准输入读取
PYTHONPATH=src python3 -m resolver < examples/request.json

# 或传入文件路径
PYTHONPATH=src python3 -m resolver examples/request.json

# 带已知冲突的示例
PYTHONPATH=src python3 -m resolver examples/conflicts.json

# 原请求无解时，显式生成最小根需求让步方案
PYTHONPATH=src python3 -m resolver --relax-roots request.json
```

## Docker Compose

```bash
# 构建
docker compose build resolver

# 通过标准输入运行
docker compose run --rm resolver < examples/request.json

# 或挂载文件并传路径
docker compose run --rm -v "$PWD:/work" resolver /work/examples/request.json
```

## 测试

测试中的“对拍”会对小目录枚举每个包的“不安装/选择某个版本”的全部组合，执行根可达闭包、冲突互斥和全部区间检查，再按相同目标选出答案，与回溯求解器结果逐一比较。覆盖：

- 3 包 × 最多 3 版本、5 包 × 最多 4 版本的随机小目录：无冲突 90 个、带随机 `conflicts` 90 个；
- 100 个 3 包随机目录的根需求放宽：全组合枚举保留根集合，分别核对撤销集大小、撤销包名字典序、保留需求闭包和三级目标，并逐个复核重新加入被撤销需求仍无解；
- 自环、互相依赖环、冲突区间、空根；
- 冲突强制回退版本、冲突贯穿依赖传播、环内冲突、冲突与过期已装版本并存；
- 放宽模式中的依赖环、冲突、过期安装版本、撤销全部根需求及空闭包；
- 删除不再可达的包、过期已装版本、包数 tie-break、完整目录向量字典序；
- CLI 成功、`UNRESOLVABLE`、根需求放宽报告和格式错误退出码。

有 pytest 时：

## 算法说明

求解器使用约束传播 + 深度优先回溯：

- 对每个已被根或依赖要求的包维护交集区间（所有下确界取 max、上确界取 min）。
- 每选一个版本，立即加入其依赖边；若区间变为空，或与已选依赖版本冲突，则回滚。
- 选择版本时同步查询 `conflicts` 双向互斥表：与任何已选版本构成已知冲突的候选直接跳过；冲突在搜索过程中检查并随回溯撤销，而不是先求出旧最优再删除冲突包。
- 待选包采用“可行版本最少优先”（MRV）以尽早发现冲突。
- 分支内版本从大到小尝试，以便先找到字典序较大的候选。
- 分支定界使用安全下界：
  - 当前必选包中无法保持已装版本的数量；
  - 当前闭包大小；
  - 乐观版本向量上界。
  这些剪枝只排除不可能优于当前最优解的分支，不改变穷举语义。
- 根需求放宽不共享上述搜索闭包：按撤销数量递增、包名字典序枚举根集合；每个集合通过不可变 `Catalog` 复制仅替换 `root`，重新调用一次完整求解，确保依赖区间传播、已选分支和冲突状态完全隔离。找到方案后再将每个撤销需求单独加回做无解复核。

目录上限只有 10 包 × 4 版本（约一百万组合量级），最坏无依赖情形下纯穷举约 6 秒；加入上述剪枝后典型/边界基准为毫秒级。放宽模式最多额外搜索 2^10 个根集合，仍在小目录约束内。
